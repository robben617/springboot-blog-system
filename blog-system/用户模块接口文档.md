# 用户模块接口文档

> 本文档基于后端真实源码（`com.example.blog`）重新生成，覆盖注册、登录、个人资料维护、管理员用户管理全部接口。
> 标注「登录」的接口指需用户已登录（持有有效 `JSESSIONID`）；标注「管理员」的接口在登录基础上还需管理员角色。
> 所有密码相关字段在示例中以占位符 `<明文密码>` / `<加密后密码>` 表示，绝不出现真实密码值。

## 二、统一约定

### 2.1 返回体结构 `Result<T>`

所有接口统一返回 `com.example.blog.util.Result<T>`，字段如下：

| 字段 | 类型 | 说明 |
|----|----|----|
| `code` | Integer | 状态码：200 成功；400 参数/业务错误；401 未登录；403 无权限/账号禁用；404 不存在；413 上传超限；500 系统错误 |
| `msg` | String | 提示信息（成功时为「操作成功」或具体文案） |
| `data` | T | 业务数据，视接口而定；无数据时字段缺省或为空 |

分页接口 `data` 为 `PageResult<T>`，字段：`pageNum`、`pageSize`、`total`、`pages`、`list`。

### 2.2 错误码表

| code | 常量 | 触发场景（真实源码） |
|----|----|----|
| 200 | `CODE_SUCCESS` | 操作成功 |
| 400 | `CODE_BAD_REQUEST` | 参数缺失/格式错误、用户名已存在、原密码错误、状态参数非法、管理员账号不可删除等 |
| 401 | `CODE_UNAUTHORIZED` | 未登录访问受保护接口（`LoginInterceptor` 拦截）；`UserManageService` 内部未取到登录态 |
| 403 | `CODE_FORBIDDEN` | 非管理员访问 `/admin/**`（`AdminInterceptor`）；账号被禁用时登录 |
| 404 | `CODE_NOT_FOUND` | 用户不存在（`/user/info`、`/user/{id}` 等） |
| 405 | `CODE_METHOD_NOT_ALLOWED` | 请求方法不被支持 |
| 413 | （上传超限） | 头像文件超过 2MB（`MaxUploadSizeExceededException`） |
| 500 | `CODE_SERVER_ERROR` | 未捕获的空指针/系统异常（`GlobalExceptionHandler` 兜底） |

> 说明：`LoginInterceptor` 与 `AdminInterceptor` 除写入 `Result` 的 `code/msg` 外，同时设置 HTTP 状态码（401 / 403），便于前端按 HTTP 状态与业务 `code` 双重判断。

### 2.3 Session 鉴权说明

- 登录成功后后端将用户标识写入 `HttpSession`：
  - `userId`（`Constants.SESSION_USER_ID`）
  - `username`（`Constants.SESSION_USERNAME`）
  - `role`（`Constants.SESSION_ROLE`，0-普通用户 / 1-管理员）
- 容器通过 Cookie `JSESSIONID` 维持会话；前端无需手动管理，请求携带该 Cookie 即可。
- `LoginInterceptor` 拦截除白名单外的全部请求：从 Session 读取 `userId`，为空则返回 401；不为空则将 `userId`/`username`/`role` 写入 `request` 属性，供 Controller 直接取用（`request.getAttribute("userId")`）。
- `AdminInterceptor` 仅拦截 `/admin/**`，校验 Session 中 `role == 1`，否则返回 403。
- 白名单（`WebMvcConfig` 中 `excludePathPatterns`）：`/login`、`/register`、`/test/**`、`/error`、`/upload/**`、`/static/**`、`/categories**`、`/tags**`、`/comments/**`、`/announcements**`、`/friend-links**`、`/articles**`。写操作路径（如 `/user/**`、`/admin/**`）均不在此列，必须登录。

## 三、接口详情

### 3.1 用户注册 — `POST /register`

- **权限**：公开
- **Content-Type**：`application/json`
- **请求体**（JSON）：

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|----|----|----|----|----|
| `username` | String | 是 | 用户名 | 见下方业务规则，3~20 位、字母/数字/下划线 |
| `password` | String | 是 | 密码（明文） | 见下方业务规则，6~20 位、须含字母和数字 |
| `email` | String | 否 | 邮箱 | 可为空，按原样入库 |

- **业务规则**（`UserController.register` + `UserServiceImpl.register`）：
  1. Controller 层基础校验：用户名/密码非空，密码长度 ≥ 6（否则 400「密码至少6位」）。
  2. `UserServiceImpl` 再校验：
     - 用户名 trim 后非空；长度 3~20；仅允许 `^[a-zA-Z0-9_]+$`，否则 400「用户名仅允许字母、数字和下划线」。
     - 密码非空；长度 6~20；须同时包含字母和数字，否则 400「密码须同时包含字母和数字」。
     - 用户名已存在 → 400「用户名已存在」。
  3. 生成 16 位随机盐（`PasswordUtil.generateSalt()`），密码以 `MD5(盐值 + 明文密码)` 加密后存储（`PasswordUtil.encrypt`）。
  4. 默认值：昵称 = 用户名、角色 = 0（普通用户）、状态 = 1（启用）。
  5. 响应中**不返回** `password` 与 `salt`。
- **成功示例**：

```json
{
  "code": 200,
  "msg": "注册成功",
  "data": {
    "id": 1001,
    "username": "alice_01",
    "nickname": "alice_01",
    "email": "alice@example.com",
    "avatar": null,
    "bio": null,
    "role": 0,
    "createTime": "2026-10-26T10:20:30"
  }
}
```

- **失败场景**：

| code | msg | 触发条件 |
|----|----|----|
| 400 | 用户名不能为空 | 用户名为空或纯空白 |
| 400 | 密码不能为空 | 密码为空 |
| 400 | 密码至少6位 | 密码长度 < 6（Controller 层） |
| 400 | 用户名长度须为 3~20 位 | 用户名长度越界 |
| 400 | 用户名仅允许字母、数字和下划线 | 含非法字符 |
| 400 | 密码长度须为 6~20 位 | 密码长度越界 |
| 400 | 密码须同时包含字母和数字 | 缺字母或数字 |
| 400 | 用户名已存在 | 用户名重复 |

### 3.2 用户登录 — `POST /login`

- **权限**：公开
- **Content-Type**：`application/json`
- **请求体**：

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|----|----|----|----|----|
| `username` | String | 是 | 用户名 | 非空 |
| `password` | String | 是 | 密码（明文） | 非空 |

- **业务规则**（`UserServiceImpl.login`）：
  1. 用户名为空或密码为空 → 400「用户名和密码不能为空」。
  2. 用户名不存在 → 400「用户名或密码错误」（不暴露是否存在，统一文案）。
  3. 账号状态为禁用（0）→ 403「账号已被禁用，请联系管理员」。
  4. 使用 `PasswordUtil.matches(明文, 盐值, 库内密文)` 校验，失败 → 400「用户名或密码错误」。
  5. 校验通过后写入 Session（`userId`/`username`/`role`）。
- **成功示例**：

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "id": 1001,
    "username": "alice_01",
    "nickname": "alice_01",
    "email": "alice@example.com",
    "avatar": null,
    "bio": null,
    "role": 0,
    "createTime": "2026-10-26T10:20:30"
  }
}
```

- **失败场景**：

| code | msg | 触发条件 |
|----|----|----|
| 400 | 用户名和密码不能为空 | 字段为空 |
| 400 | 用户名或密码错误 | 用户不存在或密码错误 |
| 403 | 账号已被禁用，请联系管理员 | 账号被禁用 |

---

### 3.3 退出登录 — `POST /logout`

- **权限**：登录
- **Content-Type**：`application/json`（无请求体）
- **业务规则**：调用 `session.invalidate()` 销毁会话；再次使用原 `JSESSIONID` 将因 `userId` 为空被拦截器判为未登录。
- **成功示例**：

```json
{
  "code": 200,
  "msg": "已退出登录"
}
```

- **失败场景**：未携带有效 `JSESSIONID` → 401「未登录，请先登录」。

- **失败场景**：

| code | msg | 触发条件 |

| 401 | 未登录，请先登录 | 未携带有效会话 |

### 3.7 修改个人资料 — `PUT /user/profile`

- **权限**：登录
- **Content-Type**：`application/json`
- **请求体**（`UpdateProfileDTO`，所有字段可选，只更新传入字段；传空串表示清空）：

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|----|----|----|----|----|
| `nickname` | String | 否 | 昵称 | 若传则不可为空白；长度 ≤ 50（与 `user.nickname` 字段上限一致） |
| `email` | String | 否 | 邮箱 | 长度 ≤ 100 |
| `avatar` | String | 否 | 头像 URL | 长度 ≤ 255；通常先用 3.9 上传拿到路径再回填 |
| `bio` | String | 否 | 个人简介 | 长度 ≤ 300 |

- **业务规则**：`userId` 取自拦截器；`null` 字段保持原值，空串清空对应字段；昵称非空校验不通过 → 400「昵称不能为空」/「昵称不能超过 50 个字符」。返回更新后的 `UserVO`。
- **请求示例**：

```json
{
  "nickname": "小艾",
  "bio": "热爱写作与分享"
}
```

- **成功示例**：

```json
{
  "code": 200,
  "msg": "个人资料修改成功",
  "data": {
    "id": 1001,
    "username": "alice_01",
    "nickname": "小艾",
    "email": "alice@example.com",
    "avatar": "/upload/2026/10/26/abc.jpg",
    "bio": "热爱写作与分享",
    "role": 0,
    "status": 1,
    "createTime": "2026-10-26T10:20:30",
    "updateTime": "2026-10-26T11:05:00"
  }
}
```

- **失败场景**：

| code | msg |
|----|----|
| 401 | 未登录，请先登录 |
| 400 | 昵称不能为空 / 昵称不能超过 50 个字符 |

> 注：返回的 `UserVO` 较 `buildUserInfo` 多出 `status`、`updateTime` 字段（管理接口与个人接口共用 VO）。

### 3.8 修改密码 — `PUT /user/password`

- **权限**：登录
- **Content-Type**：`application/json`
- **请求体**（`ChangePasswordDTO`）：

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|----|----|----|----|----|
| `oldPassword` | String | 是 | 原密码（明文） | 非空 |
| `newPassword` | String | 是 | 新密码（明文） | 同注册规则：6~20 位，须含字母和数字 |

- **业务规则**：`userId` 取自拦截器；原密码或新密码为空 → 400「原密码和新密码不能为空」；原密码校验失败 → 400「原密码错误」；新密码按注册规则校验（长度 6~20、须含字母和数字）。校验通过后以新盐值重新加密存储。
- **请求示例**：

```json
{
  "oldPassword": "<原密码明文>",
  "newPassword": "<新密码明文>"
}
```

- **成功示例**：

```json
{
  "code": 200,
  "msg": "密码修改成功"
}
```

- **失败场景**：

| code | msg | 触发条件 |
|----|----|----|
| 401 | 未登录，请先登录 | 未携带有效会话 |
| 400 | 原密码和新密码不能为空 | 字段为空 |
| 400 | 原密码错误 | 原密码不匹配 |
| 400 | 密码长度须为 6~20 位 | 新密码越界 |
| 400 | 密码须同时包含字母和数字 | 新密码缺字母或数字 |

### 3.9 上传头像 — `POST /user/avatar`

- **权限**：登录
- **Content-Type**：`multipart/form-data`
- **请求参数**：

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|----|----|----|----|----|
| `file` | MultipartFile | 是 | 头像图片 | 大小 ≤ 2MB；格式限 jpg/jpeg/png/gif/webp（复用 `FileUploadUtil`） |

- **业务规则**：上传成功后返回文件相对访问路径（形如 `/upload/yyyy/MM/dd/xxx.jpg`）；前端一般再用 3.7 将路径写入 `avatar` 字段。超限 → 413「上传文件过大，请压缩后重试」；非图片格式由 `FileUploadUtil` 拒绝。
- **成功示例**：

```json
{
  "code": 200,
  "msg": "头像上传成功",
  "data": "/upload/2026/10/26/abc.jpg"
}
```

- **失败场景**：

| code | msg | 触发条件 |
|----|----|----|
| 401 | 未登录，请先登录 | 未携带有效会话 |
| 413 | 上传文件过大，请压缩后重试 | 超过 2MB |

| code | msg | 触发条件 |

| 403 | 无权限，需要管理员身份 | 非管理员 |

|----|----|----|
| 401 | 未登录，请先登录 | 未登录 |
| 403 | 无权限，需要管理员身份 | 非管理员 |
| 400 | 状态只能是 0（禁用）或 1（启用） | status 非法 |

### 3.12 删除用户 — `DELETE /admin/user/{id}`

- **权限**：管理员
- **Content-Type**：`application/json`（无请求体）
- **路径参数**：`id`（Long，目标用户 ID）
- **业务规则**：逻辑删除；级联删除该用户发布的全部文章、草稿与评论（文章-标签中间表为物理删除）。**管理员账号不可被删除** → 400「管理员账号不可被删除」。
- **成功示例**：

```json
{
  "code": 200,
  "msg": "删除用户成功"
}
```

- **失败场景**：

| code | msg | 触发条件 |
|----|----|----|
| 401 | 未登录，请先登录 | 未登录 |
| 403 | 无权限，需要管理员身份 | 非管理员 |
| 400 | 管理员账号不可被删除 | 目标为管理员 |
| 404 | 用户不存在或已被删除 | 目标用户不存在 |

### 3.13 重置密码为系统初始密码 — `PUT /admin/user/{id}/reset-password`

- **权限**：管理员
- **Content-Type**：`application/json`（无请求体）
- **路径参数**：`id`（Long，目标用户 ID）
- **业务规则**：系统不提供自助密码找回，由管理员在后台将该用户密码重置为**系统初始密码**（后端硬编码，经新盐值加密存储）。接口本身不返回初始密码明文，重置后需通过其他渠道（如站内通知）告知用户。
- **成功示例**：

```json
{
  "code": 200,
  "msg": "密码已重置为初始密码"
}
```

- **失败场景**：

| code | msg | 触发条件 |
|----|----|----|
| 401 | 未登录，请先登录 | 未登录 |
| 403 | 无权限，需要管理员身份 | 非管理员 |
| 404 | 用户不存在或已被删除 | 目标用户不存在 |

## 四、与前端页面的对应关系

前端目录：`blog-frontend/src`

| 前端文件 / API | 对应后端接口 |
|----|----|
| `views/Login.vue`（`loginRules` 校验：用户名 3-20、密码 6-20） | `POST /login`（`api/user.js → userApi.login`） |
| `views/Register.vue`（`registerRules` 校验：用户名 3-20 且 `^[a-zA-Z0-9_]+$`、邮箱格式、密码 6-20 且含字母和数字、两次密码一致） | `POST /register`（`api/user.js → userApi.register`） |
| `views/Profile.vue` | `GET /user/info`、加载时 `GET /user/stats`；「基本资料」→ `PUT /user/profile`；「修改密码」→ `PUT /user/password`；头像上传 `beforeAvatarUpload` 校验图片且 <2MB → `POST /user/avatar`（`api/user.js`） |

## 五、补充说明

1. **密码存储**：采用 `MD5(盐值 + 明文密码)`，盐值为 16 位随机串，每次注册/改密重新生成。登录与校验均通过 `PasswordUtil` 完成，响应体永不返回 `password` / `salt`。
2. **用户角色**：`role` 0=普通用户、1=管理员；注册默认 0，仅能通过数据库或后台初始化管理员。
3. **逻辑删除**：用户、文章、评论均为逻辑删除（`deleted` 标记），仅文章-标签中间表为物理删除。
4. **静态资源**：头像等上传文件经 `/upload/**` 映射本地目录；该路径在白名单内，游客可直接访问图片。
5. **本文档范围**：仅覆盖用户模块（`UserController`、`UserProfileController`、`AdminUserController`）。`/admin/stats`、`/admin/articles` 等其余后台接口不属用户模块，未列入。
