# 分类标签评论模块接口文档

> 覆盖范围：文章分类（Category）、标签（Tag）、评论（Comment）。
> 数据库表：`category`、`tag`、`article_tag`、`comment`。
> 至此，本接口文档与《用户模块接口文档》《文章模块接口文档》《公告友链文件上传模块接口文档》共同覆盖后端全部 48 个业务接口（`/test/health` 为健康检查接口，不属于业务接口）。

## 一、全局约定

### 基础信息

| 项目 | 值 |
|------|------|
| Base URL | `http://localhost:9090` |
| 协议 | HTTP/JSON |
| 认证方式 | Session Cookie（登录后自动携带 JSESSIONID） |
| Session 超时 | 30 分钟 |

### 路径约定

| 前缀 | 说明 |
|------|------|
| `/categories`、`/tags`、`/comments/**` | 公开只读接口，游客可访问（`WebMvcConfig` 放行） |
| `/admin/category`、`/admin/tag` | 写操作，**需管理员**（`AdminInterceptor` 拦截） |
| `/comment`（单数） | 发表 / 删除评论，**需登录**（`LoginInterceptor` 拦截） |

### 统一返回格式

```json
{ "code": 200, "msg": "操作成功", "data": null }
```

> 业务异常（参数校验失败、资源不存在、越权等）由 `GlobalExceptionHandler` 统一处理：**HTTP 状态恒为 200**，错误信息在 `body.code` / `body.msg`；仅拦截器拒绝时返回真实 HTTP 401 / 403。

### 统一状态码

| code | 说明 |
|------|------|
| 200 | 成功 |
| 400 | 请求参数有误（名称为空/超长/重复、分类下有文章禁止删除等） |
| 401 | 未登录（HTTP 层直接返回） |
| 403 | 无权限（非管理员调用 /admin/**；非作者非管理员删除评论） |
| 404 | 分类 / 标签 / 文章 / 评论不存在 |
| 500 | 服务器内部错误 |

### 通用分页结构（PageResult）

`GET /categories/{id}/articles`、`GET /tags/{id}/articles` 的 `data` 均为：

```json
{
  "pageNum": 1,
  "pageSize": 10,
  "total": 2,
  "pages": 1,
  "list": [ { "文章简要对象 ArticleBriefVO" } ]
}
```

| 分页参数 | 类型 | 必填 | 默认 | 说明 |
|---------|------|------|------|------|
| pageNum | Long | 否 | 1 | 页码，非法值由 `PageUtils` 归一化为 1 |
| pageSize | Long | 否 | 10 | 每页条数，非法值归一化为默认值 |

ArticleBriefVO 字段：`id`、`title`、`summary`、`cover`、`viewCount`、`categoryId`、`categoryName`、`createTime`、`authorId`、`authorNickname`（只返回已发布、未删除的文章；`categoryId` / `categoryName` 供列表卡片展示所属分类）。

## 二、分类接口（5 个）

### 1. 分类列表（公开）

```
GET /categories
```

**响应示例**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    { "id": 1, "name": "后端开发", "sort": 1, "createTime": "2026-09-01 08:00:00" }
  ]
}
```

排序：`sort` 升序、`id` 升序。

### 2. 按分类浏览文章（公开，分页）

```
GET /categories/{id}/articles?pageNum=1&pageSize=10
```

| 路径参数 | 说明 |
|---------|------|
| id | 分类 ID |

错误：分类不存在 → `code=404, msg=分类不存在`。

### 3. 新增分类（管理员）

```
POST /admin/category
Content-Type: application/json
```

| 参数 | 类型 | 必填 | 校验 |
|------|------|------|------|
| name | String | 是 | 去首尾空格后非空，≤ 50 字符，**不可与已有分类重名** |
| sort | Integer | 否 | 不传默认 0，值越小越靠前 |

**请求示例**：`{ "name": "人工智能", "sort": 6 }`

**成功响应**：`{"code":200,"msg":"新增分类成功","data":{"id":6,"name":"人工智能","sort":6,"createTime":"…"}}`

**失败响应**：

| 场景 | body |
|------|------|
| name 为空 / 纯空格 | `code=400, msg=分类名称不能为空` |
| name 超 50 字符 | `code=400, msg=分类名称不能超过 50 个字符` |
| 名称重复 | `code=400, msg=分类名称已存在` |

### 4. 修改分类（管理员）

```
PUT /admin/category/{id}
```

请求体同新增（`sort` 不传则保持原值）；重名校验排除自身。分类不存在 → `code=404, msg=分类不存在`。

### 5. 删除分类（管理员）

```
DELETE /admin/category/{id}
```

**业务规则：分类下存在文章时禁止删除**（不是级联删除，也不是把文章分类置空）：

```json
{ "code": 400, "msg": "该分类下还有 3 篇文章，无法删除；请先将文章移到其他分类或删除文章", "data": null }
```

分类为空时返回：`{"code":200,"msg":"删除分类成功","data":null}`。

## 三、标签接口（5 个）

### 1. 标签列表（公开）

```
GET /tags
```

排序：按标签名 `name` 升序。响应结构同分类列表，元素为 `{ id, name, createTime }`。

### 2. 按标签浏览文章（公开，分页）

```
GET /tags/{id}/articles?pageNum=1&pageSize=10
```

经 `article_tag` 关联表查询携带该标签的已发布文章，返回 PageResult&lt;ArticleBriefVO&gt;。标签不存在 → `code=404, msg=标签不存在`。

### 3. 新增标签（管理员）

```
POST /admin/tag
Content-Type: application/json
```

| 参数 | 类型 | 必填 | 校验 |
|------|------|------|------|
| name | String | 是 | 去空格后非空，≤ 50 字符，**不可重名**（数据库层有唯一索引 `uk_tag_name`，业务层提前拦截） |

**请求示例**：`{ "name": "Spring Cloud" }`

**失败响应**：`code=400`，msg 为「标签名称不能为空」「标签名称不能超过 50 个字符」「标签名称已存在」之一。

### 4. 修改标签（管理员）

```
PUT /admin/tag/{id}
```

只可修改名称，重名校验排除自身；标签不存在 → `code=404, msg=标签不存在`。

### 5. 删除标签（管理员）

```
DELETE /admin/tag/{id}
```

**业务规则：删除标签时在同一事务内自动解除该标签与所有文章的关联（删除 `article_tag` 对应行），文章本身不受影响。** 成功返回 `{"code":200,"msg":"删除标签成功"}`。

> 说明：文章与标签的关联维护（全量覆盖式更新）由文章模块在发布 / 编辑文章时内部调用 `TagService.replaceArticleTags` 完成，**不单独暴露 HTTP 接口**。

## 四、评论接口（3 个）

评论采用**两级结构**：一级评论（`parentId` 为空）挂在文章下；回复（`parentId` 指向一级评论）展示在该评论下方。回复不支持继续嵌套——对回复再回复时，系统自动归并到它所属的一级评论下。

### 1. 评论展示（公开）

```
GET /comments/article/{articleId}
```

返回两级树（一级评论的 `replies` 数组承载其回复）：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    {
      "id": 1,
      "articleId": 1,
      "userId": 3,
      "userNickname": "李四",
      "userAvatar": null,
      "parentId": null,
      "content": "写得非常清晰……",
      "createTime": "2026-09-02 11:00:00",
      "replies": [
        { "id": 3, "userNickname": "张三", "parentId": 1, "content": "感谢支持！……", "replies": [] }
      ]
    }
  ]
}
```

说明：只返回未逻辑删除的评论；不暴露评论人邮箱、密码等敏感字段；父评论被删除时其回复作为一级评论展示，避免回复凭空丢失。

### 2. 发表评论 / 回复评论（需登录）

```
POST /comment
Content-Type: application/json
```

当前登录用户由拦截器写入，**无需也不能在 body 中传 userId**。

| 参数 | 类型 | 必填 | 校验 |
|------|------|------|------|
| articleId | Long | 是 | 文章必须存在且未删除（草稿也可被评论的前提是文章存在；实际展示入口仅已发布文章） |
| content | String | 是 | 去首尾空格后非空，≤ 500 字符 |
| parentId | Long | 否 | 不传/ null = 一级评论；非空 = 回复，父评论必须存在且属于同一篇文章 |

**请求示例**

```json
{ "articleId": 1, "content": "写得不错，收藏了！", "parentId": null }
```

**成功响应**：`{"code":200,"msg":"评论成功","data": { CommentVO（含 userNickname / userAvatar / createTime / replies:[]）}}`

**失败响应**

| 场景 | body |
|------|------|
| 未登录 | HTTP 401 |
| articleId 缺失 | `code=400, msg=文章ID不能为空` |
| content 为空 | `code=400, msg=评论内容不能为空` |
| content 超 500 字 | `code=400, msg=评论内容不能超过 500 个字符` |
| 文章不存在或已删除 | `code=404, msg=文章不存在或已删除` |
| 父评论不存在 | `code=404, msg=要回复的评论不存在或已删除` |
| 父评论属于别的文章 | `code=400, msg=要回复的评论不属于该文章` |

### 3. 删除评论（需登录）

```
DELETE /comment/{id}
```

**权限规则**：
- 管理员（role=1）：可删除全站任意评论；
- 文章作者：可删除自己文章下的任意评论；
- 其他登录用户：`code=403, msg=无权限删除该评论（仅管理员或文章作者可删除）`。

注意：评论人**不能**删除自己发表的评论（需求只授予管理员与文章作者）。

**业务规则**：删除为**逻辑删除**（`deleted=1`）；删除一级评论时其下所有回复一并逻辑删除。成功返回 `{"code":200,"msg":"删除评论成功"}`；评论不存在 → `code=404, msg=评论不存在或已被删除`。

## 五、权限矩阵

| 接口 | 游客 | 普通用户 | 文章作者 | 管理员 |
|------|:----:|:--------:|:--------:|:------:|
| GET /categories、/tags | ✅ | ✅ | ✅ | ✅ |
| GET /categories/{id}/articles、/tags/{id}/articles | ✅ | ✅ | ✅ | ✅ |
| GET /comments/article/{articleId} | ✅ | ✅ | ✅ | ✅ |
| POST /admin/category、/admin/tag | ❌ 401 | ❌ 403 | ❌ 403 | ✅ |
| PUT/DELETE /admin/category/{id}、/admin/tag/{id} | ❌ 401 | ❌ 403 | ❌ 403 | ✅ |
| POST /comment | ❌ 401 | ✅ | ✅ | ✅ |
| DELETE /comment/{id} | ❌ 401 | 仅自己文章下评论 | ✅（自己文章下） | ✅（全站） |
